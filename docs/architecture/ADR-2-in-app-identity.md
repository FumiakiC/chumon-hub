# ADR-2: 認証認可を Cloudflare Access からアプリ内 CIAM へ

- 状態: 決定（暫定）2026-07-25
- 関連: [ADR-3](ADR-3-sequencing.md)（Access 撤去の順序）／[ADR-5](ADR-5-database.md)（選定基準への影響）／計画書「決定事項と未決事項」の「アプリ内認証」／計画書 §3.2 とエポック0 の申し送り「#301 由来: 認証の置き場所とボディバッファ」

## 背景 / 課題

Access（入口ゲート）と CIAM は別カテゴリである。
これは「乗り換え」ではなく**アプリ内アイデンティティ層の新設**で、Phase 5（DB）と密結合する。

## 決定（暫定）

アプリ内アイデンティティは **Auth0 を想定**する。
AppUser（role: admin/user、所属部署、is_active）はアプリ DB 側に持ち、Auth0 はアイデンティティの提供に限定する。
Access は ADR-3 の順序どおり当面併存する（二層のトラスト境界）。

## 影響範囲 / 依存

DB 選定（ADR-5）の基準から、「Supabase Auth 一体」の優位性は外れる。

## 次アクション

Phase 4.5 で、Auth0 の現行プランと Next.js SDK を一次情報で最終確認し、暫定から確定へ移す。
